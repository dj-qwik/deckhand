# DECKHAND: Zero-G Rampart

A real-money browser siege game. Two to four crews each get a yard with a reactor. Every match is two rounds: **build** (30 s weld walls, 30 s arm turrets), then **30 s of fire**. Hold the button to draw walls block by block, or to lay a line of mortars. Seal your reactor inside an unbroken ring of walls, bolt turrets onto the floor you've enclosed, and flatten everyone else.

**Winning:** after two rounds the crew with the most base left wins. Base = reactor HP + every wall cell and turret still standing. A destroyed reactor is out, whatever else stands. Ties go to reactor HP, then damage dealt to reactors, then total damage dealt, then a seeded draw.

**Money:** every crew pays the same entry into an on-chain escrow on Robinhood Chain. The winner gets 90% of the pot, the house (owner wallet) 10%, in one transaction. Two independent co-signers replay the whole match from its input log before the contract will pay. Unfilled, abandoned or crashed matches refund everyone in full.

## What's in the box

| Path | What it is |
| --- | --- |
| `game/sim/` | Deterministic integer-only simulation shared by server, co-signers and browser. `rules.js` holds every balance number. |
| `game/sim/arenas.js` | The five arenas: Rust Dock, Reactor Graveyard, Freightliner Nine, Acid Refinery, Vacuum Bay 6. Each has one telegraphed hazard and a twist at 15 s. |
| `game/sim/bots.js` | Practice bots (they send ordinary inputs, never touch internals). |
| `server/` | Node server: HTTP API, static client, WebSocket match rooms at 20 Hz, sign-in, lobbies, chain watcher, settlement, Postgres. |
| `server/cosigner.mjs` | A co-signer. Embedded as two child processes by default; can also run on another host with `--http`. |
| `contracts/src/DeckhandEscrow.sol` | Escrow: operator-permitted seats, auto-lock when full, 2-of-n EIP-712 co-signed payout 90/10, refunds, pause, 2-day admin handover. |
| `apps/wallet/` | Privy bridge (React, built by Vite to `/wallet/wallet.js`). Exposes `window.DHWallet`. Google + email login, embedded wallet only. |
| `public/` | The game client: rotated 2.5D canvas renderer with painted textures, HUD, screens, synth audio, text-only crew chatter. |
| `tools/` | Tests: determinism, bot acceptance, network, full cash end-to-end on anvil. |

## Run it locally

```bash
npm install --include=dev
npm run build            # builds the Privy wallet bridge
PORT=10000 npm start     # practice works with no configuration at all
```

Open http://localhost:10000, click **Practice yard**. Cash play needs the environment below.

Tests:

```bash
npm run contracts:test               # forge, 20 escrow tests
node tools/determinism.mjs 6         # replays match server results exactly
node tools/accept.mjs all 40         # lazy strategies must lose; 2/3/4-crew fairness
node tools/nettest.mjs               # real server over WebSocket
DATABASE_URL=postgres://… node tools/cash-e2e.mjs [--mainnet]   # needs anvil; drops DECKHAND tables
```

## Configuration (Render environment)

| Variable | Meaning |
| --- | --- |
| `CHAIN_ID` | `46630` testnet (default) or `4663` mainnet |
| `RPC_URL` | Optional. Defaults to Robinhood's public RPC for the chain. The public endpoints are rate-limited; use a provider for production. |
| `OWNER_ADDRESS` | Your wallet. Becomes treasury (receives the 10%), guardian (can pause/refund) and, after 2 days, escrow admin. |
| `PRIVY_APP_ID` | Public Privy app ID. Never put the Privy App Secret anywhere. |
| `OPERATOR_SECRET`, `COSIGNER_A_SECRET`, `COSIGNER_B_SECRET` | Generated by Render. Server and co-signer keys are derived from these. Never paste them anywhere. |
| `DATABASE_URL` | Postgres. Required on mainnet. |
| `STAKES` | Entry tiers in ETH, default `0.001,0.005,0.01` |
| `ESCROW_ADDRESS`, `ESCROW_DEPLOY_BLOCK` | Pin after the first deploy (the log prints them). |
| `ALLOW_RAW_KEYS_ON_MAINNET` | Must be `i-understand` before mainnet will run cash matches. |

## First deploy (testnet)

1. **Render:** New → Blueprint → choose `dj-qwik/deckhand`. It creates the web service, a Postgres database and a secret group with generated keys. `OWNER_ADDRESS` and `PRIVY_APP_ID` are already filled in.
2. **Privy dashboard** (app `cmvjg6x5h01tl0hjw4k5g2735`): set it to production, add the Render URL (for example `https://deckhand.onrender.com`) under allowed origins, and switch on Google and email logins (a blank Google client ID/secret is fine).
3. Open `/status` on your Render URL. It shows the **gas wallet** address. Send it about 0.005 testnet ETH. The server deploys the escrow by itself once funded.
4. Keep refreshing `/status` until every row is green. Then copy the escrow address and deploy block from the log into `ESCROW_ADDRESS` / `ESCROW_DEPLOY_BLOCK`.
5. From your owner wallet, call `acceptDefaultAdminTransfer()` on the escrow after 2 days to take over admin.

## Before mainnet

This is the lean setup: the server key and both co-signer keys live in the same Render account, so **whoever controls Render (or the GitHub repo that auto-deploys) controls the results of matches in progress**. Players are protected against everything except that: unfilled lobbies, crashes and stalled settlements all refund in full, and any match still unsettled 2 hours after locking can be refunded by anyone.

Recommended before real money:
- Move one co-signer to a separate host with `node server/cosigner.mjs --http` and its own secret; make your owner wallet a Safe.
- Use a paid Render Postgres and a paid RPC provider.
- Turn on 2FA for Render and GitHub.
- Get legal advice on paid skill contests where your players are. The sign-in signature records a 21+ and entertainment-only statement per wallet (`GET /api/consent/:wallet`).

Then set `CHAIN_ID=4663` and `ALLOW_RAW_KEYS_ON_MAINNET=i-understand`, fund the gas wallet with real ETH, and check `/status` again.
